## GitHub Pagesに公開する（無料）

事前準備: GitHubアカウント。

1. GitHubで新しい**公開リポジトリ**を作ります（例: `chaos-relic-p2p`）。GitHub FreeでPagesを使う場合、通常は公開リポジトリが必要です。
2. ZIPを展開し、次の7個のファイルを**リポジトリの直下**へアップロードしてコミットします。
   - `index.html`
   - `style.css`
   - `app.js`
   - `engine.js`
   - `network.js`
   - `pycards.js`
   - `.nojekyll`（空ファイル）
3. GitHubリポジトリの **Settings → Pages** を開き、**Build and deployment → Deploy from a branch** を選択します。
4. ブランチは `main`、フォルダーは `/ (root)` にし、**Save** を押します。
5. GitHub Pagesへの反映を待ち、提示された `https://<ユーザー名>.github.io/<リポジトリ名>/` を開きます。
6. 部屋を作成すると7文字の部屋コードが表示されます。「招待リンクをコピー」を友達に送るか、部屋コードを知らせてください。
7. 友達が参加したらホストが「対戦開始」を押します。

**Firebase方式はホストが退出した場合に参加者へ自動引き継ぎします。** P2P／WebSocket中継ではホストが抜けると部屋が終了するため、ホスト側のブラウザを開き続けてください。

静的ファイルはCloudflare Pagesなどにも置けます。常設NodeサーバーやGASは不要です。

## カード工房でPython風スクリプトを書く

**例：攻撃で相手に与えた実ダメージの半分を回復**

```python
def on_hit():
    dealt = damage_dealt()
    recovery = min(8, dealt // 2)
    if recovery > 0:
        heal("self", recovery)
```

**例：HPが少ないときだけ守護神を呼ぶ**

```python
def on_play():
    if my_hp() < 20:
        summon("self", "phoenix", 3)
    else:
        shield("self", 6)
```

**例：防御時に受けたダメージに応じて反撃**

```python
def on_defend():
    received = damage_taken()
    if received > 0:
        damage("target", min(10, received))

def on_block():
    heal("self", 3)
```

`on_play` はカード使用時、`on_hit` は防御処理後にダメージが当たったとき、`on_defend` は防御カード使用時、`on_block` は完全防御時、`on_turn_start` は守護神の効果が続く間の自ターン開始時に実行されます。

### 値を読む関数

| 関数 | 戻り値 |
|---|---|
| `damage_dealt()` | 直前の攻撃が対象に与えた実ダメージ（防御・バリア・守護神による軽減後） |
| `damage_taken()` | 直前の防御で自身が受けた実ダメージ |
| `my_hp()` / `target_hp()` | 自分・相手のHP |
| `my_mp()` / `target_mp()` | 自分・相手のMP |
| `my_gold()` / `target_gold()` | 自分・相手のコイン |
| `round_number()` | 現在のラウンド数 |
| `has_status("target","poison")` | 毒などの状態異常があるかどうか |
| `chance(0.5)` | 50%の確率で `True` |
| `randint(1,6)` | 1〜6の乱数（上下限はそれぞれ−30〜30） |
| `min` / `max` / `abs` / `round` / `int` | 基本的な数値関数 |

### 効果を起こす関数

| 関数 | 効果 |
|---|---|
| `damage("target", n)` | nダメージ |
| `heal("self", n)` | n回復 |
| `status("target", "poison", 3)` | 状態異常を3ターン付与 |
| `shield("self", 8)` | バリアを追加 |
| `resource("self", "mp", 3)` | MPを増やす（負数も可） |
| `draw("self", 2)` | 山札から補充 |
| `cleanse("self")` | 状態異常を消す |
| `summon("self", "phoenix", 3)` | 守護神を召喚 |
| `phenomenon("meteor")` | 超常現象を発生 |
| `steal("gold", 5)` | 相手からコインを奪う |

対象は `self`、`target`、`everyone`、`all_enemies`、`random_enemy`。状態異常は `poison`, `burn`, `freeze`, `curse`, `weak`。守護神は `phoenix`, `turtle`, `sprite`, `storm`, `muse`。

### 対応するPython構文と制限

**通常のPythonを実行しているわけではありません。** `pycards.js` は対応するPython構文だけをパースし、安全な命令として実行します。ブラウザや相手のPCで任意コードを走らせません。

対応: `def on_...():`、変数代入、`+=` `-=`、括弧と数値計算 `+ - * / // % **`、文字列、比較演算、`if / elif / else`、論理演算、上記の関数。イベントごとに変数は初期化されます。

非対応: `import`、任意の自作関数、`for` / `while`、オブジェクト属性・ファイル・ネットワーク操作、無制限のプログラム。3500文字、95行、180構文ノード、1回20効果などの上限があります。1効果の数値は最大20、ダメージ・HPなどはゲーム上の上限も適用されます。

**手順**: ヘッダーの「カード工房」→ カードの種類・威力などを入力 → `card_effect.py`へコードを書く →「構文チェック」→「マイカードに保存」→ 部屋の待機室で「追加」。試合途中の追加はできません。カードは自分のブラウザの `localStorage` に保存されるため、ブラウザデータを消すとカードも消えます。

## P2Pの仕組み・制限

- GitHub Pagesが配信するのは **HTML/CSS/JavaScriptだけ** です。通信を始めるときにPeerJSの無料公開シグナリングサービスを使います。
- 接続が成立した後、ゲームデータはWebRTC DataChannelで送受信します。GASの約3秒ごとのポーリングは使いません。ゲームデータが直接届くまでの速度は接続品質に左右され、実際の遅延時間を保証するものではありません。
- **TURNリレーは設定していません**。モバイル回線・学校のファイアウォール・対称NATなど、直接通信できない環境では接続に失敗します。無料シグナリングサービスの稼働状況にも依存します。
- ホストがゲームの正しい状態、乱数、相手の手札を保持する**ホスト権威方式**です。ホストを信用する仲間内のゲーム向けで、ホストが改造すれば不正可能です。
- WebRTC P2Pではホストがページを閉じると部屋は終了します。Firebase方式はホスト引継ぎ用チェックポイントを実装済みです。タブをリロードしただけでも部屋から切断されるので注意してください。
- 相手の画面には自分の手札は通常送られません。ただしホストのブラウザには全員の手札が保持されています。
- ルームは招待コードでのみ参加可能。公開サービスとして不特定多数に提供する場合は、追加の認証・荒らし対策が必要です。

## 大学・学校Wi-FiでP2Pが使えない場合（無料のWebSocket中継）

WebRTCを禁止する学内ネットワークやファイアウォールでは、通常のPeerJS P2P通信は成立しないことがあります。WebRTCではなく **wss:// (443ポート)** で通信する中継方式を実装しました。

Cloudflare Workers + SQLite-backed Durable Objectsの無料枠で実行できます。**このGitHubリポジトリにあるのはソースコードです。CloudflareのWorker自体は自動デプロイされていません。** Cloudflareアカウントから1回デプロイしてください。

1. Cloudflareアカウントにログインし、このGitHubリポジトリをPCへcloneします。
2. ターミナルで `cd relay-worker` を実行。
3. `npx wrangler login` を実行してCloudflareへのアクセスを許可。
4. `npx wrangler deploy` を実行。初回はWorkerとSQLite-backed Durable Objectが作成されます。
5. 表示される `https://chaos-relic-relay.<サブドメイン>.workers.dev` の **https://をwss://にしたURL** を控えます。
6. リポジトリの **[relay-config.js](./relay-config.js)** を開いて `window.CHAOS_RELAY_URL = 'wss://実際のWorkerのホスト名.workers.dev';` に変更し、mainへコミットしてください。ここに実際のURLを一度設定するだけで、GitHub Pagesを開く全員に共通設定が届きます。
7. ゲームの「📡 通信」で Cloudflare WebSocket が「利用可能」になるので選びます。新規訪問者にはCloudflareが自動的に標準方式として適用されます。ほかのプレイヤーへは部屋の招待リンクを共有するだけで構いません。

**注意事項**

- このモードはWebRTCを使いませんが、ネットワーク側でWebSocket自体が禁止されていれば接続できません。
- CloudflareはWebSocketメッセージを参加者へ中継するだけなので、ホストを閉じると部屋が終了します。Firebaseは最新のRulesを公開すると、参加者が新ホストを引き継げます。
- 自作カードによる不正や荒らしを防ぐ必要がある場合は、認証・レート制限・セキュリティルールを追加してください。身内の非公開ルームを想定しています。
- Cloudflare無料枠には利用量の制限があり、将来的なサービス条件の変更にも影響されます。
- 中継方式を使わないときは「📡 通信」で「WebRTC P2P」を選択します。Firebaseも同じ画面から選択できます。
- **ブラウザにURLやFirebase設定を貼り付ける欄はありません。** 通信方式だけ選択します。サイトに共通Cloudflare URLがまだない場合は「管理者による設定待ち」と表示され、既存のFirebase設定（[firebase-config.js](./firebase-config.js)）が初期方式になります。
- [Cloudflare Durable Objectsガイド](https://developers.cloudflare.com/durable-objects/get-started/) / [WebSocketガイド](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)

中継ルーティングのローカル模擬テスト：`node tests/relay-worker.test.mjs`。



## 2026-10-13：防御インフレ＆盾狩りアップデート

- **防御札は最大18枚まで同時選択できます**（持ち札の上限）。すべての防御札の威力が合計されます。複数の反射カードを重ねたときは反射もそれぞれ発動します。攻撃札を重ねる上限は従来どおり3枚です。

- スマホのカードアイコン左上には、⚔（攻撃）、🛡（防御）、✦（奇跡）、🧪（道具）、👼（守護神）、☄（超常現象）の種別バッジを常時表示します。

### 相手の防御札の数で攻撃を増幅する

\`\`\`python
def on_play():
    shields = target_defense_cards()
    boost_attack(shields * 9)
\`\`\`

\`target_defense_cards()\` は狙った相手の防御札所持枚数、\`my_defense_cards()\` は自分の防御札所持枚数を返します。\`boost_attack(n)\` は直前に使用した攻撃の「防御前の威力」に n を追加し、相手は防御札で軽減できます（直接HPを減らす関数ではありません）。

### 自作防御札でさらに防御を積み増す

\`\`\`python
def on_guard():
    danger = incoming_damage()
    boost_defense(danger // 2 + my_defense_cards() * 5)
\`\`\`

\`on_guard()\` は通常の防御値を計算する前、選んだ防御カードごとに発動します。\`incoming_damage()\` で相手から来る攻撃の威力を読めます。\`boost_defense(n)\` は防御値を n だけ加算します（防御タイミングでのみ有効です）。

**安全性:** スクリプトはPythonの制限されたサブセットだけを実行します。外部コードは実行しません。数値が大きくてもゲーム中のループ回数には安全制限があります。

変更のテスト: \`node tests/guard-hunt.test.js\`（多重防御、18枚使用、重ね反射、相手の防御札カウント、自作カードの攻防威力追加）。

### 数値・処理上の注意

- 数値は JavaScript の **安全な整数（最大 9,007,199,254,740,991）** の範囲で正確に表現します。これはゲームバランス制限ではなく、ブラウザの数値精度を守るための制約です。それ以上の精密な整数を扱うには、ゲーム全体をBigInt方式に移行する必要があります。
- **無制限に配列やスクリプトを実行できるわけではありません。** 1回の「カードを引く」処理では最大64枚を補充し、スクリプト文字数・実行ステップ数・1イベント効果数にはフリーズ防止の上限を残しています。手札の合計枚数にはゲームルール上の固定上限を設けませんが、極端な枚数はFirebaseの通信量と端末メモリを圧迫します。
- Python風コードはブラウザ上の**制限付きPython構文サブセット**であり、一般的なPythonのimport・ループや任意ライブラリは動きません。
- 既存カードのスクリプトに \`min(8, ...)\` などの記述がある場合、その上限は**カード作者が記述した能力上の制限**です。必要に応じて書き換えてください。
- 最新のロジック検証は \`node tests/inflation-python.test.js\`、従来の盾狩り検証は \`node tests/guard-hunt.test.js\` で再現できます。ページ更新後は友達同士で新しい部屋を作成してください。

## 2026-10-15: 自作カードAPI基盤・オリジナルポップ演出

コードタブで**関数名または効果の日本語説明から関数検索**ができます。Monaco Editorにもゲーム専用APIの入力補完を登録しました。カードの能力を作るための読み取り関数52種類、操作・演出関数29種類をサポートします。

例（Goldを増やしたあと、計算結果を全員へ金色ポップ表示）：

```python
card.name = "黄金の大博打"
card.type = "item"
card.effect = "gold"
card.power = 0
card.cost = 0

def on_play():
    bonus = hand_count("target", "defense") * 50 + 300
    resource("self", "gold", bonus)
    popup("黄金の祝福", "防御札 {hand_count('target', 'defense')}枚 × 50 + 300 = {bonus} Gold! / 所持 {self.gold}G", "💰", "gold")
    battle_log("Gold +{bonus} を獲得")
```

`popup(title, detail, icon, theme)` のテーマは `magic`（紫）、`danger`（赤）、`success`（緑）、`gold`（金）、`info`（青）です。`{bonus}` のようなローカル変数、`{self.hp}` のようなプレイヤー値、`{hand_count('target','defense')}` のような式も置換できます。`format("名前 {self.name}")` は文字列として結果を返します。ポップはゲーム状態に保存され、**Firebase・P2P・中継を含む各プレイヤーへ同期**されます。

そのほか `draw_type()`（種類指定ドロー）、`duplicate()`（カード複製）、`clear_hand()`、`set_hp()`、`set_resource()`、`swap_stat()`、`give()`、`heal_percent()`、`alive_count()`、`hand_power()` などを追加しています。全83関数・使い方は **[CARD_API.md](./CARD_API.md)** に記載しています。

コード工房では「🎬 ポップ」などのテンプレートを押して挿入でき、「🧪 実行テスト」で実際の計算後の値とポップの見た目を確認できます。大量のポップによる表示スパムを防ぐため、1回のカードイベントで表示する演出は6件、保持する演出の履歴は12件までです。表示テキストはHTMLとして実行しません。

## 2026-10-17：演出BUSY・同じポップの動的更新・虹色グラデーション

カスタムカードの演出を **ホスト側の対戦進行と同期するbusyシステム**に刷新しました。ポップの表示時間が残っている間、他のプレイヤー操作・CPU・次のターン・時間切れ処理は進みません。すべての演出が終了した時点で自動解除し、画面に次の操作ができるようになります。ホストの時計を基準にするため、切断したクライアントからのACK待ちによる無限停止は起こりません（busy最大24秒）。

- **`popup(title, detail, icon, theme, duration_ms)`**：1つのポップを開始します。表示時間をミリ秒で指定できます。
- **`popup_update(title, detail, icon, theme, duration_ms)`**：ポップ枠を保持したまま、文字・変数・アイコン・色を次の段階へ切り替えます。省略した項目は前のステージの値を引き継ぎます。
- **`popup_wait(duration_ms)`**：現在のステージの表示時間を延ばします。
- **グラデーション演出**：`rainbow`（虹色）、`aurora`（オーロラ）、`sunset`（夕焼け）、`neon`（ネオン）を追加。従来の `magic` / `danger` / `success` / `gold` / `info` も使えます。
- **カード工房**：実行テストで複数ステージをまとめて再生し、例として「🌈 パチンコ演出」テンプレートを追加しました。ヘッダーの関数図鑑にも83関数と新しい演出例が掲載されます。
- **ネットワーク**：busy期限とステージ一覧を、すべての通信方式でプレイヤーごとの画面状態に同期します。勝利確定時にも最後のポップを表示し、終了後に対戦結果を確定します。
- **安全対策**：ポップは最大6個/コードイベント、1つ最大12ステージ、合計busyは最大24秒。テキストはHTMLとして実行されず、動きを減らすOS設定にも対応します。

制約：カード効果（ダメージ・Gold変更など）の数値処理は**カード発動時に同期的に確定**します。busyが待たせるのは**次の操作・CPU・ターン進行・タイムアウト**です。カード効果の数値計算まで段階別に遅延実行する機能ではありません。

関数の詳細・コピー用のカードコードは [CARD_API.md](./CARD_API.md) を参照。検証は `node tests/popup-busy-timeline.test.js` と `node tests/popup-stages-ui.test.js`、従来の `tests/card-popup-ui.test.js` を使用します。


**Cloudflare中継の運用注意（再デプロイが必要）**：段階演出による対戦データが増えても不必要に接続を閉じないよう、[relay-worker/src/worker.js](./relay-worker/src/worker.js) の受信サイズ制限を旧65,000文字から262,144文字へ拡張しました。GitHub Pagesだけ更新してもCloudflare Worker側には反映されません。中継を利用中なら、開発PCの `relay-worker` フォルダで `npx wrangler deploy` を再実行してください。新しい中継経路の検証は `node tests/relay-worker-large-popups.test.mjs` です。
